Desmake CMS API

Operations publishing API — push News, Blog and FAQ to the live site without a rebuild.

1 · API key required

Every request must carry the shared ops key in the Authorization header (or the x-cms-key header).

cms_f1c937598ec12189d2d67a1d01fbf18d79c6ed97568e870d

This key is stored only as a Cloudflare Worker secret (CMS_API_KEY); it is not in the image or git. To rotate, run wrangler secret put CMS_API_KEY.

2 · Base URL

https://desmake.com — all endpoints are under /api/cms.

3 · Endpoints

MethodPathPurpose
POST/api/cms/postsCreate a post (news / blog / faq)
GET/api/cms/postsList posts (filters below)
GET/api/cms/posts/<id>Fetch one post by its id
PUT/api/cms/posts/<id>Update a post (partial)
DELETE/api/cms/posts/<id>Delete a post

All endpoints require the API key. GET list params: type (news|blog|faq), status (published|draft), limit (≤200), offset.

4 · Post fields (POST / PUT body)

FieldTypeRequiredNotes
typestringyesOne of news, blog, faq
titlestringyesHeadline / question
body_mdstringyesMarkdown body (start with ## headings; the title is shown separately)
slugstringnoURL slug; auto-generated from title if omitted
excerptstringnoSummary / answer-preview
cover_imagestringnoAbsolute image URL
authorstringnoDefaults to Desmake
tagsarrayno["ai-art","news"]
statusstringnopublished (default) or draft
published_atnumbernoEpoch ms; defaults to now

5 · Example — publish a News post

curl -X POST https://desmake.com/api/cms/posts \
  -H "Authorization: Bearer cms_f1c937598ec12189d2d67a1d01fbf18d79c6ed97568e870d" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "news",
    "title": "Desmake launches agent storefronts",
    "excerpt": "Creators can now let AI agents sell for them.",
    "tags": ["product", "agents"],
    "body_md": "## What changed\n\nWe shipped a new MCP endpoint so agents can publish on your behalf.\n\n## Why it matters\n\nLess manual work, more reach."
  }'

6 · Public pages (auto-rendered)

  • /news and /news/<slug> — News & updates
  • /faq and /faq/<slug> — Q&A
  • /blog and /blog/<slug> — merges the static pillar posts with API-published blog posts

7 · Notes

The API is live only after the CMS build is deployed. If a request returns 401, the key header is missing or wrong. If it returns 500 on create, the D1 schema may not have been applied yet (it is created automatically on first container start).
  • Markdown is rendered with the site's own renderer (headings, lists, tables, links, inline code). Start the body at ## — the page already shows the title above it.
  • Drafts are not shown publicly; set status:"published" to go live immediately.
  • Every published post is auto-added to the XML sitemap.
