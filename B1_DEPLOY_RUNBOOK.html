6. 风险点与回退方案

风险点 A — /cdn-cgi/image/ 在 Worker 源站下的行为
image-loader.ts 生成 /cdn-cgi/image/<opts>/<src>。Cloudflare 的 Image Resizing 通常在边缘拦截 /cdn-cgi/image/ 并在取源（我们的 /cdn/<key> → R2）后缩放。但若 CF 把 /cdn-cgi/ 也路由到该 Worker（OpenNext worker 接管了 /*），则无对应路由会 404，导致全部图片破裂。

验证：部署后跑第 1 项校验。若 404 → 回退方案：新增 src/app/cdn-cgi/image/[...path]/route.ts，在其中调用 env.IMAGES 绑定的 images.resizing()/draw() 返回缩放结果，并把 loader 改为指向该路由（或由 IMAGES 绑定的 fetch 形式提供）。
风险点 B — Stripe Node SDK 在 workerd
使用 nodejs_compat + compatibility_date 2026-08-20，node:crypto 可用。需实测 webhook 验签（constructEvent）。若 workerd 下报错，改用 @stripe/stripe-js 仅客户端 + 服务端以 fetch 直连 Stripe API 验签。
已知限制（非阻塞）
  • Demo 模式生图轮询为单 isolate：未配置 AGNES_API_KEY 时，合成输出仅存于创建 isolate 的内存；跨 isolate 轮询会停在 queued。生产 AI 模式（落 D1）跨 isolate 正确。
  • analytics 事件 flush：依赖 ctx.waitUntil（best-effort），低频流量在累计满 50 条时批量写入；极低频下个别事件可能延迟落库（不丢，下个事件触发）。
  • 会话/订单的内存缓存：与旧容器模型一致的设计——内存为热缓存，D1 为真相源，读请求回退 D1。跨 isolate 偶发读到刚冷启动前的旧缓存快照，属既有权衡，非 B1 回归。

7. 回滚

  • Worker 名同为 desmake。回滚 = git revert B1 提交后重新 pnpm deploy，或保留上一次 .open-next 产物重新 wrangler deploy。
  • D1 / R2 数据不受影响（绑定保持不变），回滚仅换 Worker 代码。
